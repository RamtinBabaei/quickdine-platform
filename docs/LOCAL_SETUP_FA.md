# اجرای پروژه در VS Code

این راهنما برای ویندوز و PowerShell نوشته شده است. برای اجرای محلی نیازی به ورود به Cloudflare یا ساخت دیتابیس آنلاین ندارید؛ دیتابیس و فضای عکس‌ها روی کامپیوتر شما شبیه‌سازی می‌شوند.

## ۱. ابزارهای لازم

- Node.js نسخه 22 LTS یا بالاتر، حداقل 22.13
- Git
- VS Code

در ترمینال VS Code نسخه‌ها را بررسی کنید:

```powershell
node --version
npm --version
git --version
```

## ۲. دریافت پروژه

اگر ZIP را دانلود کرده‌اید، آن را Extract کنید و پوشه‌ای را در VS Code باز کنید که فایل `package.json` داخل آن است.

اگر از گیت‌هاب می‌گیرید:

```powershell
git clone https://github.com/RamtinBabaei/quickdine-platform.git
cd quickdine-platform
code .
```

## ۳. نصب وابستگی‌ها و تنظیم محیط

از منوی Terminal گزینه New Terminal را باز کنید و اجرا کنید:

```powershell
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
Copy-Item .dev.vars.example .dev.vars
```

داخل `.dev.vars` مقدار `DEMO_MODE="true"` قرار دارد. این گزینه سه دموی مستقل برای مشتری، صاحب رستوران و مدیر فعال می‌کند. اطلاعات ورود واقعی یا کلید محرمانه‌ای لازم نیست.

اگر PowerShell اجرای `pnpm.ps1` را مسدود کرد، در همین دستورات از `pnpm.cmd` به‌جای `pnpm` استفاده کنید؛ نیازی به تغییر سیاست امنیتی سیستم نیست.

## ۴. ساخت اولیه و راه‌اندازی دیتابیس

```powershell
pnpm build
pnpm db:local
pnpm dev
```

ترمینال را باز نگه دارید. آدرس پیش‌فرض:

**http://localhost:5173**

اگر پورت اشغال بود:

```powershell
pnpm dev -- --port 5174
```

در این حالت آدرس چاپ‌شده در ترمینال را باز کنید. برای متوقف کردن سرور از `Ctrl+C` استفاده کنید.

در اجراهای بعدی، معمولاً فقط `pnpm dev` لازم است. بعد از تغییر ساختار دیتابیس، ابتدا build و سپس `pnpm db:local` را اجرا کنید. این دستور فقط migrationهای اجرا‌نشده را اعمال می‌کند.

## ۵. بررسی عملکرد

۱. آدرس http://localhost:5173/api/health را باز کنید. باید وضعیت `ok` و مقدار `database: true` را ببینید.

۲. در صفحه اصلی، دموی **The restaurateur** را انتخاب کنید.

۳. از بخش Restaurants رستوران **Your Rooftop Atelier** را پیدا کنید. تاریخ فردا، تعداد مهمان و ساعت را انتخاب کنید، یک توضیح در Special requests بنویسید و رزرو را ثبت کنید.

۴. در **Management → Reservations** رزرو را Confirm کنید. توضیح واردشده باید در کارت رزرو نمایش داده شود.

۵. در **My bookings** وضعیت رزرو را بررسی کنید. صفحه را Refresh کنید؛ اطلاعات باید باقی بماند. رزرو را Cancel کنید و تغییر وضعیت را ببینید.

۶. برای آزمایش مدیر، از دمو خارج شوید و در صفحه اصلی **The administrator** را انتخاب کنید. درخواست رستوران نمونه را Approve یا Reject کنید.

۷. برای حساب شخصی، Sign up را بزنید. رمز عبور حداقل ۱۰ کاراکتر لازم دارد. برای حساب صاحب رستوران، گزینه I manage a restaurant را انتخاب کنید. حساب مدیر واقعی فقط با دسترسی اپراتور به دیتابیس ساخته می‌شود.

هر دمو فضای مستقلی دارد. انتخاب دموی جدید، فضای جدیدی می‌سازد؛ مدیر یک دمو به اطلاعات دموی دیگر دسترسی ندارد.

## ۶. اجرای بررسی‌های کد

```powershell
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm build
```

برای اجرای خروجی production روی کامپیوتر:

```powershell
pnpm start
```

آدرس پیش‌فرض این حالت معمولاً http://localhost:8787 است؛ آدرس دقیق ترمینال را استفاده کنید.

این پروژه دموی نمونه‌کار است: ثبت رزرو، تأیید، لغو، حساب‌ها و مدیریت اطلاعات واقعاً در دیتابیس انجام می‌شوند، اما هیچ رستوران واقعی‌ای تماس یا رزرو دریافت نمی‌کند. پرداخت و ارسال ایمیل در این نسخه وجود ندارد.
